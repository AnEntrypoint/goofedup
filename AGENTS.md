# AGENTS.md -- goofedup

## Purpose and philosophy
- Cross-platform structural-anomaly watcher: catches malware by SHAPE (size ratios, entropy, path, lineage, launcher configs), not signature. Born from one incident: Discord bootstrap ballooned 40 B -> 270 KB, `.orig` backup sibling kept, obfuscated `node -e` C2, Recycle Bin full of stray Go/JS files.
- Alert-only. Nothing kills, deletes or blocks, and no alert prescribes a remedy. Only write path: opt-in `--scan-deps PATH --fix`, which quarantines to `~/.goofedup/quarantine` (never deletes).
- No trust-by-name exemptions: the real payload was disguised as trusted automation. Trust (name, vendor root, signature) only raises a bar; it never removes it. A false positive costs seconds, a false negative costs the machine.
- No comments in code (owner rule). Names carry meaning; non-obvious WHY lives only in this file.

## Build and verify
- No test suite, no test files, ever. Verify by live-witnessing the real code path against real files and processes.
- `cargo build --release` and `cargo build --release --features gui --bin goofedup-gui` must finish with zero warnings (a non-Windows `unused_mut` on `bootstrap_watch` in `Config::default_for_platform` is pre-existing). CI also runs `cargo check --release --all-targets` on windows/macos/ubuntu. `cargo check --target x86_64-unknown-linux-gnu` / `aarch64-apple-darwin` catch cfg-gated breakage locally.
- Live checks: `goofedup --show-config` (under a scratch USERPROFILE; byte-stable), `goofedup --scan-deps .` (own tree must exit 0), `goofedup --audit` (Windows posture audit; exit 1 on any Critical), `--help`/`-h`/`--version` (clap help is user-visible text).
- Incident-shaped fixture (must exit 1): tasks.json with `runOn: folderOpen` running `node ./x/fa-solid-400.woff2`, settings.json with `task.allowAutomaticTasks: true`, `.gitignore` containing `config.bat`, and a woff2 whose bytes start with `global['!']=`. Defender may block such files: build them from string fragments at runtime.
- The scanner reads raw workflow text, so CI fixtures must build trigger strings from fragments (never spell `pull_request_target`, `curl | sh` or `${{` literally) or goofedup flags its own workflow. `dtolnay/rust-toolchain` pinned by SHA needs an explicit `toolchain:` input.
- Log message text, alert category strings, config JSON keys and CLI flags are matched by other code and by user log readers: never rename them. clap help must stay explicit `help =`/`long_about` strings (`///` docs on `Args` would be derived into help text).
- Commits are attributed to lanmower only. Every Windows `Command::new` needs `creation_flags(CREATE_NO_WINDOW = 0x0800_0000)` or the console-less GUI flashes a window per spawn.

- `main.rs` CLI modes and thread startup; `bin/goofedup_gui.rs` + `gui/*` tray GUI (`--features gui`, Windows).
- `alert.rs` single alert channel (console + log + callbacks); `correlate.rs` merges c2-shaped-process with backup-sibling/bootstrap-size into CONFIRMED-COMPROMISE.
- `config.rs` defaults, overrides, `config_sections()`; `config_reload.rs` override-file hot reload; `tamper_config.rs` audit/tamper settings.
- `heuristics.rs` pure detectors (entropy, obfuscation score, encoded-command decode, masquerade, homoglyph, HiddenSpawn shapes, backup-sibling naming).
- `watch_process.rs` process poll (path, c2 shape, file-read burst); `watch_file.rs` notify-driven bootstrap growth and backup siblings; `watch_network.rs` scans and firewall drift; `watch_persistence.rs` services/tasks/run keys/launchd/cron diffs; `watch_tamper.rs` periodic Windows posture audit; `watch_events.rs` Windows event-log push consumer with `event_rules.rs`; `watch_repos.rs` live repo-compromise watcher.
- `scan_js.rs` one-shot hidden-unicode/packed-payload scan, asar reader, alert-response scan, `--fix` restore; `scan_repo.rs` repo launcher checks (tasks.json, settings, .gitignore, package scripts, hooks, workflows); `repo_fix.rs` quarantine remediation; `command_shape.rs` command-line dropper shape; `jsonc.rs` JSON-with-comments parse/key removal; `electron_sweep.rs` hourly sweep of installed Electron/VSCode apps.
- `trust.rs` WinVerifyTrust/catalog signature and hash pins; `process_trust.rs`, `lineage.rs`, `image_integrity.rs` signature/parent/image-hash detectors.
- `audit_win.rs` + `audit_win/*` one-shot Windows posture audit (accounts, acl, autoruns, certs, credentials, defender, firewall, hosts, net_exposure, registry, services, tasks, wmi, shell, pathing).
- `self_protect.rs` data-dir/override-file ACL hardening and tamper checks; `win_identity.rs` SIDs/elevation; `sysmon_config.rs` + `sysmon/goofedup-sysmon.xml` recommended Sysmon config (`--sysmon-config`, never applied).

## Config and hot-reload
- Defaults are `DEFAULT_*` consts in `config.rs`, built by `Config::default_for_platform()`. `ConfigOverrides` (all-`Option` mirror) is merged by `apply_overrides` from `~/.goofedup/goofedup.config.json`. A `Vec` override replaces the default list wholesale. `deny_unknown_fields` is off so old and new binaries tolerate each other's files.
- `SharedConfig` is `Arc<RwLock<Arc<Config>>>`: each poll clones the inner Arc once (consistent snapshot), `apply_reload` swaps it, so a reload lands on the next poll.
- `config_sections()` is the single field list behind `--show-config` and the GUI window: add every new field there (five were once missing). Overridden rows get the suffix " (from config file)".
- Reload polls override-file mtime+size every `poll_interval_secs` (no notify watcher). Startup with a broken file -> platform defaults; at runtime one WARN per changed fingerprint and keep last-known-good; deleted file -> defaults; missing file silent. Parse failure is WARN, never CRITICAL. A file rejected by `self_protect::untrusted_override_reason` counts as a parse failure.
- `poll_interval_secs` (3) governs only the polling fallbacks (process/connection enumeration, firewall state, override reload); persistence re-audits run at 10x it, firewall at 5x.

## Calibration and false-positive facts
### Process watch and file-read burst (`watch_process.rs`, config defaults)
- Polling via `sysinfo` is deliberate (WMI/kqueue/netlink would need per-OS code). A fresh `System::new_all()` per poll is mandatory: on Windows sysinfo 0.33 returns empty `cmd()` from the second `refresh_processes` on, silently disabling the c2 heuristic.
- Linux read counter is `rchar` from `/proc/[pid]/io`; `read_bytes` counts block I/O only and reads 0 for cached reads. Elsewhere `disk_usage().total_read_bytes`.
- Absolute floor 300 MiB/poll (`DEFAULT_FILE_READ_BURST_ABSOLUTE_BYTES_PER_POLL`); the old 50 MB floor gave 223 CRITICALs in one log with zero true positives (grep, tar, dllhost, Code, zig). The floor exists to catch a fast scanner on first observation, before any baseline.
- Persistence: `read_burst_required_spikes_in_window` (2) hits within `read_burst_window_size` (4) polls, not back-to-back; a zero-delta poll is a non-spike, never a history wipe (a wipe rule never accumulated past one spike; found with syncthing). Single-poll false positives seen: firefox, Discord, agentplug-runner (hundreds of MB of WASM), python.
- Trust relaxation: `known_high_throughput_tool_names` or an exe under `os_vendor_roots` multiplies thresholds by `known_high_throughput_tool_multiplier` (16.0, raised from 6.0: syncthing showed 62x-121x relative spikes, 65.1 MB vs 549 KB baseline, clearing the old 48x bar; now 8.0 x 16.0 = 128x). Cap: `file_read_burst_uncorroborated_ceiling_bytes` (2 GiB) stops any trust exemption (grep.exe fired at ~141 MB on repo greps before the cap existed). Highest legitimate burst seen: 1.2-1.7 GB/poll from claude.exe and powershell.exe (claude.exe startup read 1.7 GB in ~3 s at 0 B baseline).
- List rationale: browsers/Electron apps (chrome, firefox, Discord) show multi-poll relative spikes against quiet-tab baselines; grep looks like harvesting (34 CRITICALs over 5 days from a big `grep -r`). agentplug-runner (gm daemon) respawns under new PIDs so it rarely has a baseline; it was once documented as listed but missing from the Vec, so keep list, docs and sysinfo-reported names in sync.
- Corroboration: a burst that also fails exec-path checks clears the absolute floor at `read_burst_corroborated_threshold_fraction` (0.25). Baseline exemption: a read within `read_burst_baseline_exemption_multiplier` (3.0) of the process's own baseline is skipped (python.exe 60 MB vs 13-24 MB average). The relative check waits for `read_burst_baseline_warm_up_floor_bytes` (512 KiB) because a quiet-tab EMA makes normal activity a huge spike. EMA (`read_burst_ema_alpha` 0.2) updates after scoring and skips spike polls, else a sustained scan launders itself into the baseline (a 3.6 MB burst lifted a ~150 KB baseline to ~700 KB in two polls; the identical second burst missed).
- `os_vendor_roots` is a strict subset of `allowed_exec_roots` and holds only elevation-required locations (Program Files, Program Files (x86), WINDIR, PythonXX at the drive root; `/Applications` + system dirs on macOS; `/usr /opt /bin /sbin` on Linux); never user-writable dev homes. False positives that shared only install location: tar.exe (Git usr/bin), Code.exe, dllhost.exe.
- Windows adds every `Python3{8..=14}` dir at the drive root to both root lists (python.org all-users installs need admin; C:\Python312\python.exe was the top process-path WARN, 34 hits). Matching is exact-prefix, so versions are listed one by one. Dev-tool homes `.cargo .rustup scoop .local .gm-tools .kimi-code` are in `allowed_exec_roots` only to silence known WARN noise; they grant no trust.
- 2026-09-30 log review: `known_high_throughput_tool_names` also holds MsMpEng, Everything, ffmpeg/ffprobe, goofedup (each burst < the 2 GiB ceiling); a locally built cargo binary (`is_local_cargo_artifact`) gets the relaxation and is not treated as an unlisted path (a dev's own `litebox_runner` fired ~120 CRITICALs). Git for Windows `getprocaddr32/64.exe` is a default `known_benign_event_sources` entry (Sysmon 8 into node/conhost).
- Unlisted-path alert fires once per exact exe path per session, in memory only (re-evaluated on restart). `deny_exec_path_fragments` (Recycle Bin, `.Trash`, `.local/share/Trash`) is an instant flag; the allowlist-gap flag is WARN, not CRITICAL.
- c2-shaped-process: matches interpreter by `name` or exe basename (Linux `p.name()` is the per-thread comm, e.g. MainThread, so `node -e` never matched on name alone). Severity is always CRITICAL regardless of parent: a real Discord-bootstrap-hijack C2 loader (fileless XOR from a hardcoded IP, "app-discord-eval") fired under a recognized dev-tool ancestor. `known_automation_parent_names` is triage context in evidence only. The parent chain is walked 4 levels (immediate parent is usually a shell: bash x3 <- claude.exe <- cmd.exe <- explorer.exe; explorer.exe excluded as ancestor of everything). Evidence carries chain, `cmdline_head` (1200 chars) and `decoded_head` (300 chars); an earlier 200-char head hid everything past the interpreter call.
- 168 c2-shaped alerts in one session came from the gm harness (exec_js spawns `powershell.exe -EncodedCommand`); README documents this class as expected noise.

### Command-line scoring (`heuristics.rs`)
- Pure, no OS calls. `max_decode_depth` comes from `Config::c2_max_decode_depth` (4; no real sample needed more than a couple of layers; bounds adversarial nesting).
- Non-routable IPs/URL hosts (loopback, RFC1918, link-local, localhost) are skipped: recurring false positives from `node -e` polling its own 127.0.0.1 test server. The real C2 used routable `23.27.13.135`. `child_process` is deliberately not an obfuscation marker (routine Node module; every hit was dev automation).
- `-EncodedCommand`/`-enc` is scored on the DECODED text (the base64 wrapper always trips blob + marker and made benign and malicious equal). Decode failure -> score raw. Decoding recurses to `max_decode_depth` (the harness nests a second `$EncodedCommand = '<base64>'` inside the first). Each layer tries UTF-16LE (accepted only if <20% non-ASCII) then UTF-8. Every occurrence of every pattern is tried in position order: priority-order matching stalls on a bare `powershell -NoProfile -EncodedCommand $EncodedCommand` line that precedes the real assignment.
- Entropy (>5.2 bits/char +3, >4.7 +1) counts only after a strong signal fired (IP, URL, blob, marker, symbol density); length alone is not corroboration. Witnessed: 4 CRITICALs at score=3 from entropy alone on dense `node -e` reading `.gm/exec-spool/*.json`; the real Discord incident scored 10 with 5+ signals.
- 4+ consecutive `\uXXXX` escapes decoding to a plain-ASCII identifier score 5 (minifiers never do this; CJK/emoji escapes never trigger). HiddenSpawn shapes: config file >=3000 B in <=50 lines scores 6 (+4 per marker); packed IIFE line >=3000 B on any JS-family file scores 8 (2026-09 acptoapi `index.js` had a 39k-byte IIFE on line 224 with trailing `}`; matches `global['!']` or `var _0x...(function(`; the packer stamps `global['!']`, only the campaign id after the bang varies); JS bytes under a font/image extension score 9 (2026-09 wave hid JS in `fa-solid-400.woff2`, which a JS-only walk never opens).
- `is_backup_sibling_name` is the single backup-naming definition shared by `watch_file`, `electron_sweep`, `scan_js`. `strip_backup_markers` peels suffixes only at the end, so `index.inz.cjs` is not a backup of `index.js` (the Antigravity/Discord compromise left both a `.orig`-style backup and an `*.inz.cjs` payload).
- `is_compiler_build_artifact_path` (`<target|*-target|*_target>/{debug,release}/{build,deps}/`; custom CARGO_TARGET_DIR names like `ap-target`)  exempts hashed cargo binaries: top WARN-tier process-path noise for Rust developers; `target/` is wiped by `cargo clean`, so it is no durable persistence spot.
- `KNOWN_NAME_HOMES` `node.exe` includes Adobe Creative Cloud Experience's bundled Node (`\adobe\adobe creative cloud experience\libs`): Authenticode Valid, genuine Node.js 18.20.2, recurs ~09:32:02 daily from a scheduled Adobe task.

### Network, file, persistence watchers
- `scan_distinct_hosts_threshold` 40 / `scan_window_secs` 10: 15 fired on browsing (chrome fans out to 15-27 CDN hosts in 10 s). Host-sweep also needs >=3 distinct ports (`HOST_SWEEP_MIN_PORT_VARIETY`): page loads are host-diverse but port-narrow (once distinct_hosts=15, ports=1). Tool multiplier applies to hosts (40 x 16 = 640) but not to port-scan alerts; chrome kept clearing 40 (46-69 hosts, 2-3 ports, 4 hits in ~11 h).
- Network is polling only. Windows uses `netstat -ano -p TCP` (avoids unsafe `GetExtendedTcpTable` FFI), names via `sysinfo`. Linux: `/proc/net/tcp` state 01 + `/proc/<pid>/fd` socket inodes; firewall tries ufw, then iptables >8 lines = "has rules". Firewall alerts only on enabled -> disabled.
- `watch_file`: notify-driven, no polling; config snapshotted at startup (roots change only on restart); `run` has no stop signal, so main's final join blocks after Ctrl+C (open issue). `unusual-growth` baselines only script extensions (js mjs cjs py rb php pl ps1 sh) and skips staging dirs (`_cacache`, `_npx`, `node_modules/.cache`, `.cache`): 229/239 CRITICALs in one session were npm staging. Baseline = smallest size ever seen; alert needs baseline <5 KiB, current >20 KiB, ratio >=10.
- `bootstrap_watch` (Windows): `%LOCALAPPDATA%\Discord` `discord_desktop_core` `index.js`, max 2048 B (real file ~40 B `module.exports = require('./core.asar')`, was overwritten with 270 KB payload). Also every npm `lib\cli.js` (`%ProgramFiles%\nodejs`, `%APPDATA%\npm`, `%ProgramData%\nvm`), max 2048 B (legit 214-419 B): npm loads that file before any lifecycle-script logic, so a payload appended there runs on every npm call even with `--ignore-scripts`. Witnessed 2026-09: 275 KB line in the user-owned `%APPDATA%\npm` copy (2026-08-11) and 1.5 MB in the Program Files copy (2026-09-23), tags `/*M260630A*/` `/*RS260605*/`, `global['e']='NPM'`.
- Persistence: if enumeration returns < half the baseline the poll is skipped and the baseline kept (2026-09-02: one PowerShell/WMI failure wiped it and ~230 services alerted as new). New entry is CRITICAL on denied path or obfuscated command, else WARN. Services/tasks via PowerShell (`Get-CimInstance Win32_Service`, `Get-ScheduledTask`); Run keys via native `RegEnumValueW`. macOS plist command is a best-effort first `<string>` after `ProgramArguments`. Kinds: service, scheduled-task, login-item, systemd, cron, launchd.
- Electron/VSCode sweep (`electron_sweep_enabled`, default on, interval 3600 s): the Antigravity IDE (VSCode fork) sat compromised 5+ weeks because live watchers see only new events and `AlertResponse` widens only after another alert names the app. Installs are found by shape (`resources/app.asar`, `node_modules/@vscode`, electron binary beside `resources`, depth <=6) under `%LOCALAPPDATA%\Programs` / `/Applications` / `~/.local/share` + `/opt`. Hourly because it does full-content scans plus whole-tree backup walks. `sweep_existing_backup_siblings` covers backups already on disk (2026-08-11 and 2026-09-19 misses). Sleeps in 500 ms steps so Quit is honored.
- Correlator: c2-shaped-process + backup-sibling/bootstrap-size within 60 s, either order (added after the 2026-08-24 and 2026-09-04 Discord hits had to be joined by hand). CONFIRMED-COMPROMISE is not an inspected category, so it cannot re-trigger itself; keep it that way.

### Scanner and remediation (`scan_js.rs`, `scan_repo.rs`)
- Assets (`command_shape::NON_SOURCE_ASSET_EXTENSIONS`) are content-sniffed on the first 64 KiB, not judged by extension. `SKIP_DIR_NAMES` is deliberately narrow (VCS dirs, `target`). `is_config_file` matches any `.config.` name. Asar: u32 at byte 4 = header pickle size H, u32 at 12 = JSON length, JSON at 16, data at 8+H; entries >50 MiB skipped.
- `AlertResponse`: any Warn/Critical alert naming an app scans its tree, 30-min per-root cooldown, slot reserved before spawning (N alerts -> one scan); ignores `hidden-unicode-identifier` and `alert-response` (own output would loop). Alerts under discord/adobe/slack/teams/electron dirs widen to the whole product root. Registered before watchers start.
- Restore only when the live sibling exists, differs, and the preserved original has no HiddenSpawn marker (restoring a tampered original completes the compromise). `--fix`: dry-run pass then apply pass for both `scan_js` and `repo_fix`; the tampered file moves to `~/.goofedup/quarantine/<path with \ / : as _>.<timestamp>` (copy failure rolls back). Origin: moving a payload aside is not restoring the live bootstrap; a hand restore without checking the original was a real mistake.
- Only CRITICAL findings drive the `--scan-deps` exit code. `--fix` quarantines WHOLE files: legit tasks in the same tasks.json need manual restore from `~/.goofedup/quarantine`. A hidden-alone folderOpen task is CRITICAL. `watch_repos` ignores node_modules/target/.git except `.git/hooks`, 250 ms debounce.

## Windows posture audit (`audit_win`)
- `collect(Tier::Native | Tier::Shell)`; Tier::Shell PowerShell is always bounded by a 25 s kill (PowerShell hangs in Limited scheduled-task contexts).
- `Finding{level,category,key,title,evidence,alert_on_change}`: `key` is baseline identity, `fingerprint()` = (level,title,evidence) is the change signal: never put pids/timestamps in title/evidence. The watcher ignores a category that shrinks to under half its baseline for 2 polls.
- ACL checks count ownership as writable (owner can rewrite the DACL). A missing path is "plantable" when the nearest existing ancestor allows adding files. Windows-shipped `@` and AppPkgId firewall rules are skipped by design. Windows Hello accounts show as PASSWD_NOTREQD.

## Trust and signatures (`trust.rs`, `process_trust.rs`, `lineage.rs`)
- WinVerifyTrust must fall back to catalog signatures or System32 files read unsigned. A copy of a Microsoft-signed file stays validly signed anywhere, so name/lineage detectors catch copies, not trust.
- `lookup()` returns None until a worker finishes; Unknown never alerts. Only Unsigned/Invalid images are hashed. Locally built cargo artifacts (`target/{debug,release}` under a Cargo.toml dir) skip the WARN (spoofable by creating a Cargo.toml; deliberate trade). goofedup's own pid is skipped. Python3xx roots are not admin-only.
- agentplug-runner.exe is unsigned and self-updating, so its hash pin breaks every update; fix = gm signs the binary and its publisher joins `trusted_publishers`. A parent that started later than the child is pid reuse.

- `is_dev_toolchain_path` (`.cargo/bin`, `.rustup/toolchains`, scoop apps, chocolatey, `@esbuild`, Python3xx Scripts) skips only the unsigned-in-user-writable WARN; corroborated CRITICALs still fire.
- `image-replaced-after-start` is WARN (not CRITICAL) when the moved image is `*.old*`/`old_*` and the original path exists again (Chrome `old_chrome.exe`, claude `.old.<ts>` self-updates); a deleted or unexplained move stays CRITICAL.
- Defender 5007 `SpyNet\LastMAPSFailureTimeString` is telemetry churn (52 WARNs), ignored. Scheduled-task `updated` events (no TaskContent, ASUS task 32x) WARN once per task name per session.

## Events, self-protection, hardened install
- `watch_events` uses EvtSubscribe push with bookmarks in `~/.goofedup/events.bookmarks.json`: Sysmon/Security XPath queries take seconds on 1 GB logs. `EvtNext` ERROR_TIMEOUT (1460) is NOT end-of-results (treating it so skipped events). Windows 11 build 26200 logs firewall changes as 2097/2099/2052/2059, not 2004-2006. First-run lookback is 1 h (6 h Defender) per channel in `event_rules::CHANNELS`; it was 24 h and a fresh bookmark replayed ~100 Criticals in 14 s. Sysmon Company is `-` for unsigned.
- Hardened data-dir ACL is user read-only: an un-hardened CLI cannot write log/config there. A user-level process can pre-create mutex `Global\AnEntrypoint.Goofedup.SingleInstance` to make the elevated instance exit (open issue). `runas /trustlevel` yields a restricted HIGH token, not medium; launch through explorer.exe for a real medium token.
- Noise: Defender flags gm `node -e` dispatch scripts as Trojan:Win32/SuspExec.SE (expected here); agentplug-runner CreateRemoteThread (Sysmon 8) is a known-benign shape.

## GUI
- Autostart (`gui/autostart.rs`) enable(): enables scheduled task `Goofedup` if it exists; else `hardened::install_default()` when elevated; else per-user HKCU Run key (no admin). disable() disables the task and clears the Run key; is_enabled() = Run key present or task enabled. Turned on once at first run (log file absent): the watcher was not running at 2 of 4 known incident timestamps (2026-08-11, 2026-09-19). REG_SZ needs a trailing UTF-16 NUL that `HSTRING::as_wide()` omits (`nul_terminated_utf16`).
- Toasts need BOTH `SetCurrentProcessExplicitAppUserModelID` (`toast::init`) and a Start Menu `goofedup.lnk` with AUMID `AnEntrypoint.Goofedup`; without the shortcut Windows silently drops every `Show()`. `shortcut::ensure_registered` is idempotent, apartment-threaded COM, tolerates RPC_E_CHANGED_MODE.
- Toast throttle: per (category, subject), 5 min (`PER_ALERT_IDENTITY_TOAST_COOLDOWN`); log and history always get every alert. The subject extraction duplicates `history::extract_group_key` (different input type): keep them in step. Toast `Activated` runs on a WinRT thread and only sets `OPEN_HISTORY_REQUESTED`, consumed by the 200 ms event-loop poll.
- Single instance via the named mutex above; a second launch exits. Tray icon is rendered at runtime (32x32 shield, 4 sub-pixel samples): cyan idle, gray paused, red Critical pending. History is in-memory, newest first, `MAX_RETAINED_ENTRIES` 200.
- `alert_window.rs`: `compute_card_layout` is stateless and recomputed on every paint/hit-test (never memoize). The feed child window is created WITHOUT `WS_VISIBLE` and shown after `GWLP_USERDATA` (`CardFeedState`) is attached: a visible child can get `WM_PAINT` inside `CreateWindowExW` before state exists, painting an empty feed with no scroll range (cause of live scroll-check failures). `OPEN_FEED_HWND` is a single slot (second window overwrites; accepted); feed `WM_DESTROY` clears it before freeing state. Refresh repaints only on `entries_fingerprint` change and re-expands only grouped cards by (category, key). ListView row height is set via a 0-image small-icon imagelist (`set_report_row_height_via_small_icon_imagelist`, intentionally never destroyed). NUL-stripping before `LVM_INSERTITEMW` and skipping empty text in owner-draw are crash guards.
- Known leak: the feed's base and bold `HFONT`s are never deleted (feed `WM_DESTROY` frees only `CardFeedState`); predates the sweep.

## Incident context
- HiddenSpawn launcher: hidden `.vscode/tasks.json` with `runOn: folderOpen` running node on `fa-solid-400.woff2`, plus `task.allowAutomaticTasks`, `config.bat` in `.gitignore`, and a decoy `public/fonts` README ("Blockchain Explorer"). Forged commits are amended tip commits keeping CI epochs with a +0200 committer tz. 2026-09-19: mass force-push wave via lanmower's `gho_` token. Two confirmed repo compromises; both delivery vectors are covered by `scan_repo`.
